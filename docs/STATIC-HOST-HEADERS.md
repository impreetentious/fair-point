# Static-host security headers

Fairpoint is a static client-side application. It has no backend, no accounts, no telemetry, and no third-party embeds; deal files stay in the browser unless you export them yourself. The policy below makes that architectural claim enforceable by the host rather than merely asserted in prose.

`vercel.json` applies these headers on Vercel and `serve.json` applies the identical policy to the local `npm run preview` build and to the Playwright suite, so every shipped surface is exercised under the real policy before release. Any alternate static host should apply the equivalent response headers to every route and static asset:

```http
Content-Security-Policy: default-src 'self'; base-uri 'self'; connect-src 'self'; font-src 'self'; form-action 'self'; frame-ancestors 'none'; frame-src 'none'; img-src 'self' data:; manifest-src 'self'; media-src 'self'; object-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; worker-src 'self'
Referrer-Policy: no-referrer
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Permissions-Policy: camera=(), geolocation=(), microphone=(), payment=(), usb=()
```

## Why each non-obvious directive is what it is

- **`worker-src 'self'`** — `src/app/register-sw.tsx` registers the offline service worker generated by `scripts/generate-sw.mjs`, and the offline contract in `tests/e2e/offline.spec.ts` depends on it. Without this directive the registration fails and the app loses offline support. It must never be widened beyond `'self'`.
- **`connect-src 'self'`** — the product itself opens no connections, so `'none'` looks tempting. It is wrong here: the service worker's `fetch` handler re-requests same-origin assets on a cache miss, and `'none'` would break the cache-fill path. `'self'` still forbids every off-origin destination, which is the property that matters. The worker already refuses any request whose origin is not its own.
- **`script-src`/`style-src` inline allowances** — required by the framework's static bootstrap and its generated critical styles. They permit no remote origin.
- **`img-src 'self' data:`** — icons are inline SVG sprites from `public/`; `data:` covers inlined raster assets. No remote image host is permitted.
- **No `blob:` anywhere.** Deal export builds a `Blob` and hands it to an `<a download>` (`src/app/App.tsx`, `src/app/screens/Report.tsx`). A download is not a fetch or a navigation, so no CSP fetch directive governs it, and the policy stays tighter for it. Adding `blob:` here would be a widening with nothing asking for it.
- **`frame-ancestors 'none'` plus `X-Frame-Options: DENY`** — Fairpoint has no embeddable surface. Both are set because some hosts and older agents honour only one.

## Changing this policy

`npm run check:csp` fails if `vercel.json`, `serve.json`, and this document disagree, if a required directive goes missing, if a wildcard or unsafe execution token appears, or if the built `out/` gains an off-origin reference. Update all three together, then re-run `npm run build && npm run gates` — the suite serves `out/` under this exact policy, so a CSP that breaks the service worker fails the gate rather than shipping.

Host-specific tuning and verification of the deployed response headers remain a deployment responsibility; this repository cannot verify headers from a live host.
